# Phase3cGPU方案

**时间**：2026-07-08 20:21
**背景**：在不大改 Phase3b 原逻辑的前提下，新增 GPU-first 训练框架，先跑通大 batch 公式生成训练闭环。

**关键决策**：
- 阶段目标 → 新增 Phase3c GPU-first 训练脚本，替代训练内循环但保留 Phase3b 逻辑（备选：直接做全新 Phase4 或继续优化 Phase3b）— 理由：当前目标是先跑通 GPU 框架，不把中间脚本长期精装修。
- GPU 默认规格 → 默认 batch_size=1024、max_len=16、小 Transformer；4090D preset 使用 batch_size=2048；4096 只手动压力测试（备选：默认 4096）— 理由：4090D 24GB 足够先跑大 batch，但第一版应先稳态跑通。
- 性能记录 → 每步记录 sample/vm/score/backward/step 耗时、吞吐、CUDA 显存；不做复杂 profiler（备选：torch profiler/nvidia-smi 采样）— 理由：轻量指标足够判断 GPU 框架价值。
- 训练与复核 → GPU 训练阶段快速算 reward，训练后只对 top formulas 用原 CPU scorer/validator 复核（备选：GPU scorer 完全复刻 CPU daily rows）— 理由：训练要速度，最终审计要可信。
- 词表支持 → 第一版 GPU VM 支持完整现有 Phase3b 词表（备选：只支持简单操作符子集）— 理由：避免改变公式空间。
- 文件组织 → 新增 scripts/phase3c_train_gpu.py、src/alpha_etf/gpt/torch_vm.py、src/alpha_etf/gpt/torch_scoring.py、tests/test_phase3c_gpu.py；不改 scripts/phase3b_train_transformer.py（备选：在 Phase3b 脚本加开关）— 理由：保留旧闭环，GPU 原型独立试错。
- 输出产物 → 沿用 Phase3b 主要结构，但默认不保存全量 sampled_formulas；需要时用 --save-sampled-formulas（备选：默认全量保存）— 理由：避免大 batch CSV I/O 拖慢训练。
- 数值精度 → 默认 float32，不启用 AMP/fp16/bf16（备选：直接混合精度）— 理由：原作者也主要使用 float32，且公式里的 DIV/RET/STD 更需要稳定性。
- reward → 第一版不加长度惩罚、极值裁剪、去冗余、signal normalization（备选：同步改 reward）— 理由：保持 Phase3b 口径，避免变量混杂。
- checkpoint → 保存 checkpoint，但第一版不支持 resume（备选：实现 --resume-from）— 理由：先跑通，不增加恢复逻辑复杂度。
- 验证 → 做 5-8 条固定公式 CPU/GPU 小样本 sanity test，不做大规模严格一致性测试（备选：不做对照或做大规模对照）— 理由：防止实现写错，同时不拖慢进度。
- 部署 → 实现后准备 AutoDL 部署和 smoke 命令；当前服务器关机，实际运行前提醒用户开机（备选：当前必须跑完服务器 smoke）— 理由：当前受服务器状态限制，但不阻塞代码实现。
- 正式 GPU 参数 → 下一版 preset 使用 batch_size=4096、train_steps=1000、max_len=12、d_model=128、num_layers=4、num_heads=4、ff_dim=512、entropy_coef=0.001，并只接 RMSNorm + SwiGLU，不接 LoRD/MTP/LoopedTransformer（备选：batch_size=2048 或一次接全套原作者增强）— 理由：GPU 框架已跑通，需要进入更真刀真枪的训练规格；但当前 2048 已接近显存上限，所以 4096 长训前必须先跑 smoke。
- 断点续训 → 正式 GPU 训练必须支持 resume，默认每 10 step 保存 checkpoint_latest.pt，可用 --resume-from 继续（备选：仍只保存最终 checkpoint）— 理由：4096x1000 已经是真训练，中途网络/硬件中断不能导致整轮作废。

**待定/未决**：
