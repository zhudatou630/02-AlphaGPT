# Phase3b训练方案

**时间**：2026-07-08 08:58
**背景**：Phase3a 已完成公式测试台，需要在进入实现前确认 Phase3b 最小训练闭环方案。

**关键决策**：
- Phase3b 目标 → 先做最小可训练闭环（备选：直接做完整增强版、继续扩 Phase3a）; 理由：当前最重要的是验证 Transformer 生成公式、VM 执行、scorer 给 reward、REINFORCE 更新、checkpoint/artifact 可复现，而不是追求收益结论。
- 生成器形态 → 小 Transformer（备选：GRU）; 理由：用户倾向长远对齐 AlphaGPT，且原作者主线也是 Transformer；第一版通过缩小规模控制复杂度。
- 原作者增强组件 → 第一版暂不接入 LoopedTransformer、QKNorm、RMSNorm、SwiGLU、MTPHead、LoRD、完整 critic（备选：直接照搬增强版）; 理由：这些组件有长期价值，但第一版同时引入会增加排错维度；后续可在 GPU 训练框架中逐步采用。
- 模型默认配置 → d_model=64、num_layers=2、num_heads=4、ff_dim=128（备选：更大模型）; 理由：基本对齐原作者小 Transformer 尺寸，适合本机 CPU 先跑通。
- 公式长度 → max_len=16（备选：12、24/32）; 理由：比原作者主线 12 略宽，给 ETF 公式留空间，同时避免第一版搜索空间过大。
- 公式结束方式 → 显式加入 BOS/EOS/PAD，支持变长公式（备选：固定长度、不加 EOS/PAD）; 理由：原作者固定长度方案能跑但语义较粗，显式特殊 token 更利于 artifact、审计和长期框架。
- action mask → 加最小结构合法性约束（备选：完全自由生成、复杂金融语义 mask）; 理由：降低非法公式比例，只保证栈结构可执行，不把金融偏见提前写进生成器。
- batch size → 64（备选：128、256+）; 理由：先在本机 CPU 跑，若太慢或闭环跑顺后再设计 GPU 版。
- train steps → 默认 500，支持 smoke 50/100（备选：1000、100/200）; 理由：默认完整试跑约 32000 条公式，足够观察闭环和日志；smoke 用于快速验证。
- reward → 合法公式沿用 Phase3a 的 scorer_mean_return，validator 不进入 reward（备选：混入 validator、改 rank-only/top-K reward）; 理由：validator 尚未设计成训练目标，尤其 raw signal 零轴对生成公式未必有交易含义。
- 坏公式惩罚 → 硬错误 -5，劣质公式 -2（备选：统一 -5、统一温和惩罚）; 理由：沿用 Phase3a/原作者风格，结构非法和非有限值重罚，常数/低覆盖轻罚。
- entropy → 默认 entropy_coef=0.0，但保留参数开关（备选：默认 0.01、完全不实现）; 理由：对齐原作者纯 REINFORCE，后续若公式多样性塌缩可打开。
- advantage → 使用标准化 advantage，即 (reward - mean) / std（备选：只减均值、raw reward）; 理由：对齐原作者 Meme 主线，适合 reward 混有正常分数和惩罚项的场景。
- critic → 第一版不使用 critic，最多预留接口（备选：直接 actor-critic、完全不留接口）; 理由：critic 有降噪价值，但会引入 value loss、权重和训练稳定性问题；后续增强版再接。
- 优化器 → AdamW，lr=3e-4，weight_decay=1e-5，gradient_clip_norm=1.0（备选：lr=1e-3、lr=1e-4）; 理由：参考原作者 A 股实验，更适合小 batch 和本机 CPU 的稳定试跑。
- checkpoint → 保存完整 checkpoint + best formula artifact（备选：只存 best formulas、每步保存）; 理由：支持复现、未来续训和配置校验。
- resume → 第一版不支持 resume，但 checkpoint 保存完整状态（备选：最小可靠 resume）; 理由：避免把训练平台复杂度提前引入，后续 GPU 长训前再补。
- RNG state → 保存 python/numpy/torch 随机状态（备选：只保存 seed）; 理由：实现成本低，有助于未来严格复现和 resume。
- 日志 → 记录完整诊断日志，包括 reward、valid/invalid、invalid 原因、公式长度、entropy、loss、耗时、avg_allowed_actions（备选：只记少数字段）; 理由：Phase3b 需要可解释训练过程，不只看最终 best formula。
- 输出目录 → 每次运行单独 run 目录，位于 data/processed/phase3b/runs/<run_id>/（备选：固定目录覆盖）; 理由：后续会比较 seed、参数、CPU/GPU 和模型结构，不能互相覆盖。
- validator 审计 → 训练后自动审计 best formulas，并新增 generated-formula 专用 rank_only variant（备选：只用现有 validator、手动审计）; 理由：Phase3a 已暴露 raw signal 零轴问题，rank_only 更符合生成公式的排序语义；不改 Phase2B 原始 validator。
- best formulas 数量 → top_n=20（备选：10、50）; 理由：延续 Phase3a，便于审计和候选池分析。
- 测试 → 新增少量核心测试（备选：只 smoke、完整大测试套件）; 理由：重点覆盖 action mask、采样器、checkpoint schema、artifact reload，不对随机训练效果做脆弱断言。

**待定/未决**：
- GPU 版训练框架暂不设计；等本机 Phase3b 跑通后，再决定更大 batch、更长 steps、增强组件接入顺序和租用 GPU 配置。
- 原作者增强组件的采用顺序暂不定；初步倾向先 action mask/训练日志稳定，再考虑 critic，之后再评估 RMSNorm/SwiGLU/QKNorm/LoopedTransformer/MTPHead/LoRD。
- rank_only validator 的具体 top-K 或分位参数实现时需对照现有 Phase2 validator/scorer 口径确定。
- 是否维护 latest 指针暂不定；实现时可用 latest_run.txt 替代符号链接以避免兼容问题。
