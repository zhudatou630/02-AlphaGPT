# Phase3a公式台

**时间**：2026-07-08 05:10
**背景**：Phase3 不直接上 Transformer/REINFORCE，先搭一个不训练模型的公式测试台，验证 token 公式、VM、scorer、artifact 的闭环。

**关键决策**：
- Phase3a 边界 → 做“不训练模型的公式测试台”（备选：直接上模型训练；只做 VM sanity）— 理由：先证明公式执行、打分、保存、复现链路可靠，再把随机生成替换成 Transformer 生成，排错维度更低。
- Phase3a 流程 → 手写/随机 token 公式 → VM 执行成 `signal [ETF, time]` → Phase2 scorer 打 reward → 保存 artifact → 重新加载 best 公式复现 → validator 外部审计（备选：只执行不打分；只打分不复现）— 理由：这是训练前最小完整闭环。
- 横截面 token → 第一版不做 `CS_RANK/CS_ZSCORE`，也不预先加入横截面特征（备选：VM 横截面算子；预计算横截面特征；只加 CS_RANK）— 理由：当前 ETF 池小，scorer/validator 已经做每日 top-K 横截面选择；横截面 token 会提前引入 mask、动态 universe、前视和排序语义复杂度。
- 基础 token → 使用时序特征 `open/high/low/close/volume/amount`（备选：只用 close；照搬 AlphaGPT meme 词表）— 理由：贴合当前 panel 数据字段，且不引入 meme 语义。
- 常数 token → 加入 `CONST_0`、`CONST_1`，暂不加更多常数（备选：不加常数；只加 CONST_1；加大量常数）— 理由：`mom_10 = close / delay(close,10) - 1`、`ma_gap = MA5/MA20 - 1` 需要 `CONST_1` 才能保留正负零轴语义；更多常数会扩大搜索空间。
- 算子范围 → 第一版只做连续数值算子：`ADD/SUB/MUL/DIV/NEG/ABS/SIGN/DELAY1/DELAY5/DELAY10/MA5/MA10/MA20/STD10/RET5/RET10/DECAY`（备选：加入 GATE/IF/MAX/MIN/CLIP）— 理由：条件/门控类 token 有用但会增加非法率、稀疏信号、零轴语义和排错难度，留到第二波表达力升级。
- 随机公式生成 → 使用栈深度约束的半受控随机生成（备选：完全随机 token；严格语法树生成；人工模板随机参数）— 理由：和 StackVM 语义一致，能显著减少明显非法公式，又不引入复杂语法树系统。
- 非法公式处理 → 不丢弃，记录 `valid=false`、`invalid_reason`，并给低 reward（备选：直接丢弃；统一 reward=0；只记录不设 reward）— 理由：后续 REINFORCE 需要知道什么公式不好；invalid_reason 可用于诊断词表和生成器问题。
- 非法惩罚 → 第一版两档：执行失败/全不可用/scorer 无有效天数 `-5`，常数信号/覆盖不足 `-2`（备选：全部 -5；更细多档）— 理由：简单区分硬失败和研究价值不足，避免第一版 reward 规则过复杂。
- 合法 reward → 使用 Phase2 scorer 的 `scorer_mean_return`，主视界固定 `N=10`；其他 scorer 指标只记录不参与 reward（备选：scorer_ann_return_proxy；median_return；hit_rate；多指标混合）— 理由：`scorer_mean_return` 是最直接的 top 分位未来 N 日平均收益；年化只是线性展示，混合指标不利于解释。
- validator 使用 → 只对 best formulas 跑 Phase2B validator 外部审计，validator 指标不进入 reward（备选：不跑 validator；每条都跑；把 validator 混入 reward）— 理由：保持 scorer/validator 分层，同时给 top artifact 一层交易约束 sanity check。
- validator 口径 → 主审计 `no_max_holding`，legacy 对照 `max_holding_10`，交易成本 `transaction_cost_bps=5`（备选：只跑 no_max_holding；改用其它成本）— 理由：与 Phase2B 口径一致。
- 产物目录 → 写入 `data/processed/phase3a/`（备选：`phase3/`）— 理由：Phase3 已拆为 Phase3-0/Phase3a/Phase3b，随机公式试车台产物应与后续训练产物分开。
- 产物文件 → `generated_formulas.csv`、`best_formulas.csv`、`best_formulas.jsonl`、`phase3a_validator_summary.csv`，可选 `random_run_summary.csv`（备选：只 CSV；落所有 daily 明细）— 理由：CSV 给人审计，JSONL 作为可复现公式 artifact；第一版不膨胀 daily 明细。
- 随机规模 → 默认 `count=300`、`seed=42`，支持命令行 `--count` 和 `--seed`，第一版单 seed（备选：100；1000；不固定 seed；多 seed）— 理由：300 足够看非法率和 reward 分布，固定 seed 便于复现和排错，参数保留扩展。

**待定/未决**：
