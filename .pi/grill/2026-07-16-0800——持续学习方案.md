# 持续学习方案

**时间**：2026-07-16 08:00
**背景**：Stage D formal证明当前Transformer很早停止探索，需要在继续封存2022 validation和2023+ final的前提下，验证模型自身能否持续提高新公式的高质量右尾。

**关键决策**：
- 研究目标 → 证明Transformer自身越学越会找，而不是优先做当前最强混合搜索系统（备选：直接用Random或混合搜索最大化最终top50）— 理由：当前要修复并验证学习机制。
- 学习主信号 → Transformer自主生成、历史首次出现、canonical不同且语义有效的新公式中，每批reward最高前10%获得统一基础正反馈（备选：全样本平均reward、只奖励历史top50、前5%或前20%）— 理由：直接推动新公式右尾，又保留每批稠密反馈。
- Archive信号 → Transformer独立top50装满后，新公式按超过batch开始时旧第50名的幅度获得额外正反馈；批末统一更新archive（备选：固定进入奖励、逐条更新门槛、Transformer/Random共用archive）— 理由：对齐最终top50并消除批内顺序依赖。
- 历史状态 → 在模型更新前做全训练历史canonical去重；同一canonical只有首次出现有资格获得正反馈（备选：仅批内去重、exact token去重）— 理由：formal后几百万次主要在跨batch重复。
- 负反馈 → 历史重复和语义无效合并为“浪费attempt组”，组内按出现频率取平均负反馈；普通但有效的新公式权重为零（备选：重复零权重、每次重复完整累加惩罚、低分新公式负反馈）— 理由：重复真实消耗预算，但负反馈总量不能随重复数无限放大。
- Loss组合 → 批内前10%组、archive改善组、浪费attempt组三组分别归一化后等权；archive组内按改善幅度分配（备选：多组手调系数）— 理由：避免无依据调参和样本数支配梯度。
- 探索底线 → 每批75% Transformer、25%合法Random；Random不参与梯度，只进入独立及合并候选库（备选：entropy、自适应比例、Random高分公式教模型）— 理由：探索不能由模型关闭，同时必须单独证明模型自身进步。
- 模型细节 → entropy coefficient由0.005改为0，继续沿用formal已有的dropout=0，整条公式log-prob求和且不按长度归一化（备选：保留旧entropy、启用dropout、按长度平均）— 理由：canonical反馈直接解决探索；延迟重算需要确定性策略概率；不额外改变公式长度偏好。
- 研究内核 → 模型尺寸、AdamW、lr=1e-3、gradient clip=1.0、公式语言、VM、scorer、训练数据保持不变；各seed从头初始化（备选：扩大模型、同步调参）— 理由：隔离学习反馈的因果作用。
- Archive范围 → 训练top50仅按Transformer单公式原始reward和canonical去重维护，不加入selection相似度、主题多样性或展示清理（备选：互补公式池）— 理由：保持V3A单公式top50研究问题不变。
- 计算调度 → Transformer无梯度生成/评分后提交CPU canonical；CPU期间GPU处理25% Random；标签完成后一次整序列teacher-forcing并反向（备选：完全串行等待、滞后策略流水线、逐token重放）— 理由：保证反馈正确并减少GPU空等和重复计算。
- 工程门 → 905上先跑50 batch；CPU等待不超过batch总时间25%，teacher-forcing不超过20%，吞吐不低于3000 attempts/s，显存余量至少5GB（备选：能跑即进入研究）— 理由：服务器按时计费，算法与流程不得明显浪费算力。
- 机制预算 → 新机制seed 101/102/103各200万总attempts，工程门通过后冻结参数连续跑完；旧Transformer和Random复用formal ledger前200万（备选：100万、新跑全部对照、看seed101后调参）— 理由：约244次更新足以观察机制，现有对照身份完整。
- 过程门槛 → 以总attempt分首/末50万；末段Transformer新canonical数至少为首段50%，且末段新公式top10%平均reward高于首段；均要求三seed平均达标且至少2/3达标（备选：逐段单调、只看最终值）— 理由：允许金融噪声，但不允许探索再次归零。
- 结果门槛 → 200万时Transformer自身curated top50高于100万，且相同canonical唯一数下平均优于Random；两项均要求三seed平均为正且至少赢2/3（备选：只比旧Transformer）— 理由：过程改善必须转化为archive和搜索效率。
- 数据边界 → 机制设计、工程门和200万实验只使用训练期；2022 validation与2023+ final继续封存（备选：用validation选机制）— 理由：保留未来统一干净门禁。

**待定/未决**：teacher-forcing与CPU canonical的真实耗时、显存和最优调度只能由905的50-batch profile确认；未通过工程门时只优化计算路径，不改研究奖励。机制实验通过后的新800万formal方案另行决策。
