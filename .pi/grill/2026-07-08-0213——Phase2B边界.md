# Phase2B边界

**时间**：2026-07-08 02:13
**背景**：Phase2A 已跑通，但 validator 把 scorer 预测视界 N 同时当作最长持有期，可能截断趋势右尾；Phase2B 只修正明显误导 Phase3 的验证口径，不把 Phase2 扩展成完整研究平台。

**关键决策**：
- validator 主口径 → `no_max_holding`，scorer 仍保留 `N=10` 主视界和 `N=5` 对照视界（备选：继续绑定 N、只额外跑无上限实验）— 理由：N 应主要作为 scorer 的预测视界，交易层不应默认强制 N 日卖出。
- legacy 对照 → 同时保留 `max_holding_10` / `max_holding_5`（备选：完全删除旧口径）— 理由：保留对照可量化最长持有期截断影响。
- 交易成本 → 单一单边 `transaction_cost_bps=5`，不拆佣金/滑点，不建最低 5 元（备选：拆成佣金+滑点、零成本）— 理由：ETF 交易规模默认超过最低佣金，Phase2B 只需一个简洁保守的净收益口径。
- 产物目录 → 旧 `data/processed/phase2/` 改名为 `phase2a/`，新产物写 `phase2b/`（备选：覆盖旧目录、混写同目录）— 理由：保留 Phase2A 基线，Phase2B 产物自洽且可追溯。
- scorer 产物 → Phase2B 完整重跑 scorer + validator（备选：只重跑 validator）— 理由：`phase2b/` 目录内形成自包含快照。
- 仓位模型 → 继续固定 3 槽等权，不做 `vol_scaled`（备选：波动率归一化对照或主口径）— 理由：Phase2B 不做策略工程优化，避免混入新的仓位假设。
- 诊断产物 → 可生成很薄的 `annual_summary.csv`、`trade_distribution.csv`、`tail_attribution.csv`，均为 diagnostic-only（备选：不生成、做更完整归因体系）— 理由：这些文件只帮助读结果，不进入 scorer / reward / validator 主排序，也不改变 Phase3 训练行为。
- 交易审计字段 → `trades.csv` 增加 `entry_decision_date`、`exit_decision_date`、`exit_flags`（备选：只保留单一 `reason`）— 理由：退出条件可能同时触发，审计字段应保留完整触发信息。

**待定/未决**：
- 未来真实交易系统的用户交易思维拟合、仓位归一化、参数网格、图表报告、OOS 严格检验均不在 Phase2B 做，留到 Transformer 公式训练和后续验证阶段。
