## Phase3 的正确定位

Phase3 是“训练闭环跑通”，不是“找到能实盘赚钱的公式”。完成标准应是工程闭环成立，而非收益漂亮：

- 能批量生成公式 token。
- VM 能稳定执行公式，非法公式不会打崩流程。
- scorer 能给每条公式 reward。
- REINFORCE 能跑若干轮并写训练日志。
- 能导出 best formula artifact。
- best formula 能重新加载、重新跑 scorer，并用 Phase2B validator 做外部审计。
- 固定公式仍作为 sanity baseline。

Phase3 不做：

- 不做严格 OOS，那是 Phase4。
- 不接纸面交易、真钱、券商接口。
- 不做仓位模型升级、`vol_scaled`、参数网格、图表报告。
- 不把 `annual_summary` / `trade_distribution` / `tail_attribution` 接进 reward。
- 不用 validator 净值直接训练模型。
- 不急着上横截面 token。

## AlphaGPT 参考源码判断

原作者核心链路确实是：

```text
Transformer sample token
→ StackVM 执行 token 公式
→ Backtest 评分
→ REINFORCE 更新生成器
→ 保存 best formula
```

源码位置：

- `references/AlphaGPT/model_core/engine.py`：训练循环。`AlphaEngine.train()` 采样公式、VM 执行、backtest 评分、REINFORCE 更新、保存 best formula。
- `references/AlphaGPT/model_core/vm.py`：StackVM。feature token push tensor，operator token pop args/apply op/push result，最后 stack 剩一个 tensor 才合法。
- `references/AlphaGPT/model_core/backtest.py`：MemeBacktest reward。该逻辑不适合 A 股 ETF，应继续用本项目 Phase2 scorer 替代。
- `references/AlphaGPT/model_core/alphagpt.py`：Transformer 生成器，含 LoopedTransformer、MTPHead、critic head。
- `references/AlphaGPT/model_core/vocab.py`、`ops.py`：公式词表和算子。

需要继承的：

- 公式 token 序列作为 artifact。
- StackVM 执行公式。
- Transformer 自回归生成公式。
- REINFORCE 用外部 reward 训练生成器。
- 训练层和执行层解耦。

不能照搬的：

- 原 `MemeBacktest.evaluate()`：包含 meme 流动性过滤、`signal > 0.85` 阈值、高手续费/滑点、drawdown penalty、`activity < 5 -> -10`、median score 等，和 A 股 ETF top 分位轮动目标不一致。
- 原数据特征：`RET/LIQ_SCORE/PRESSURE/FOMO/DEV/LOG_VOL` 是 meme 语境特征，不适合作为 ETF 起步词表。
- 原执行层：Solana/Jupiter/链上交易逻辑和 A 股 T+1 完全不同。
- 原复杂模型增强不应第一版全搬：LoopedTransformer、MTPHead、LoRD regularization 可以参考，但最小闭环先用简单生成器更利于排错。
- 原 critic head 虽定义了，但训练循环实际没有用 critic 做 advantage；Phase3 可以先用 batch mean/std baseline，critic 留接口即可。

## 建议的 Phase3 工程路线

### Step 1：公式表示与词表

新增建议模块：

- `src/alpha_etf/gpt/vocab.py`
- `src/alpha_etf/gpt/ops.py`
- `src/alpha_etf/gpt/vm.py`

起步词表建议只做时序 token：

- feature：`open`、`high`、`low`、`close`、`volume`、`amount`，优先使用 qfq 价格和 raw volume/amount 的明确口径。
- operator：`ADD`、`SUB`、`MUL`、`DIV`、`NEG`、`ABS`、`SIGN`、`DELAY1`、`DELAY5`、`DELAY10`、`MA5`、`MA10`、`MA20`、`STD10`、`RET5`、`RET10`、`DECAY`。

注意：先不要上横截面 token。当前 ETF 池小且固定，执行层 top-K 已经做横截面选择；过早加入 `CS_RANK/CS_ZSCORE` 会扩大搜索空间和排错难度。

### Step 2：先做 VM，不直接上 Transformer

目标：手写 token 公式能执行成 `[N,T]` signal，且能复现固定公式的一部分，例如 `mom_10`。

建议验收：

- `RET10(close)` 或等价 token 公式输出与 `formulas.mom_10(panel)` 数值接近。
- 非法公式返回错误对象或 `None`，训练流程不会崩。
- NaN/inf 处理明确，不静默生成全 0 信号后冒充合法公式。

### Step 3：随机公式生成器

在 Transformer 之前，先做随机公式生成器跑通：

```text
随机合法/半合法 token 序列
→ VM 执行
→ Phase2 scorer 评分
→ 记录 formula/reward/invalid_reason
```

这一步是为了隔离问题。如果随机公式链路都不稳，直接接 Transformer 会难以定位。

### Step 4：最小 Transformer 生成器

新增建议模块：

- `src/alpha_etf/gpt/model.py`
- `src/alpha_etf/gpt/train.py`
- `scripts/phase3_train_formulas.py`

第一版不必搬 AlphaGPT 的 LoopedTransformer/MTPHead/LoRD。建议用小模型：embedding + positional embedding + 2 层 causal Transformer 或 GRU 均可，重点是能 sample token 和返回 log_prob。

输出至少包括：

- token 序列
- token 名称序列
- log_prob
- entropy（可选）

### Step 5：REINFORCE 训练循环

训练目标使用 Phase2 scorer，主视界建议先用 `N=10`。`N=5` 可作为评估列，不作为第一版 reward 混合目标。

最小 loss：

```text
advantage = (reward - batch_mean) / (batch_std + eps)
loss = -sum(log_prob) * advantage
```

非法公式处理建议：

- VM 执行失败：低 reward，例如 `-5`。
- 全 NaN / 覆盖不足 / 常数信号：低 reward，例如 `-2` 或 `-5`。
- 合法但 scorer 无有效天数：低 reward。
- 记录 `invalid_reason`，不要只丢弃。

### Step 6：训练产物

建议输出目录：`data/processed/phase3/`。

建议产物：

- `training_log.csv`：step、batch reward 均值/分位、best reward、非法率。
- `generated_formulas.csv`：每条公式、reward、合法性、invalid_reason。
- `best_formulas.csv`：去重后的 top 公式。
- `best_formulas.jsonl`：公式 artifact，包含 token ids、token names、scorer config。
- `phase3_validator_summary.csv`：best formulas 用 Phase2B validator 外部审计后的结果。

不要把 Phase2B 的 diagnostic CSV 接进 reward；它们只在训练后读结果。

## 关键设计提醒

- scorer 和 validator 分层不要打破。Phase3 reward 只用 scorer，validator 只做外部审计。
- 公式合法性比模型复杂度更关键。先把 VM、mask、NaN、非法公式原因做清楚。
- 不要追求第一轮 reward 好看。Phase3 验收是闭环和 artifact 可复现。
- 固定公式要继续保留为 sanity baseline，尤其是 `mom_10`、`ma_gap_5_20`。
- 如果用 torch 实现 VM/scorer，需要注意和现有 numpy/pandas Phase2 scorer 的数值一致性；最小版本也可以先用 numpy VM，训练时牺牲速度换可读性。
- 当前数据口径仍是 `qfq_latest`，不是严格 point-in-time 复权。Phase3 先接受这个限制，Phase4/OOS 前再评估。
- Phase3 暂不碰实盘接口。

## 建议第一天任务切片

1. 建 `src/alpha_etf/gpt/` 包。
2. 实现 `vocab.py`、`ops.py`、`vm.py`。
3. 写一个小脚本或测试，手写 token 公式复现 `mom_10`。
4. 实现随机公式生成器，跑 100-1000 条公式过 scorer，输出 `generated_formulas.csv`。
5. 确认非法率、reward 分布和 best formula 可复现后，再接 Transformer。

## 风险与边界

- Phase3 不是收益验证阶段。不要因为第一批生成公式收益不高就改 validator 或仓位模型。
- 不要把 AlphaGPT 原 scorer 搬进来；它是 meme 币策略，不是 A 股 ETF top 分位 scorer。
- 不要一次性迁移原作者所有模型增强。先最小闭环，再决定是否引入 critic、LoRD、多 seed。
- 不要在当前 Phase2B diagnostic 产物上做过深策略解释；它们是审计视角，不是训练目标。
