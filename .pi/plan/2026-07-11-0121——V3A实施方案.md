## 1. 结论与实施原则

V3A 不应在旧 V1/V2 VM 和 scorer 上继续追加条件分支，而应建立独立的
`research_v3a` 研究层，仅复用已经稳定的 Transformer policy、基础张量工具和
checkpoint 原子落盘思路。

当前第一阻塞不是模型，而是数据契约：正式 V3 dataset 只有相对 OHLC；事件复权绝对
OHLC 只存在于本地治理长表。V3A 必须先生成一个同时绑定绝对 OHLC、相对 OHLC、
tradable mask 和上游 V3 身份的新 dataset。公式 VM 只能读取预计算的 40 个无尺度因子，
不得注册裸 OHLC、volume 或 amount 终端。

执行顺序固定为：

```text
技术规格冻结
  -> V3A dataset 与 ResearchSpec
  -> 40 个基础因子
  -> 参数化语言 / builder / CPU VM
  -> 因果 scorer
  -> 去重漏斗 / artifact / checkpoint
  -> 本地测试与固定公式 sanity
  -> 人工停点
  -> GPU smoke 与 100,000 x 3 随机 baseline
  -> 人工确认正式预算
  -> Transformer 正式训练与同预算随机对照
  -> 2022 筛选
  -> 冻结后 2023+ 最终审计
```

在阶段 C 完成前不得启动正式训练；最终样本外结果一旦打开，不允许回到前序环节调参。

## 2. 冻结的数值规格

### 2.1 基础数据符号

设事件复权绝对价格为 `O_t/H_t/L_t/C_t`，全市场统一交易日历上的前一日为 `t-1`。
因子只在所需输入全部有效时计算。价格分母必须有限且大于 0，否则结果为 `NaN`；不在
价格分母上加固定 `1e-12`，因为固定 epsilon 会破坏逐 ETF 缩放不变性。

区间宽度 `H-L` 为 0 时，`CLV` 和 `RSV` 取 0，含义是无振幅日不给方向性位置判断。
所有输出使用 `float64` 生成 CPU 参考真值，GPU 训练缓存使用 `float32`。

### 2.2 11 个因子族

固定单日因子：

| 因子 | 定义 | 值越大表示 |
|---|---|---|
| `DAYRET` | `C_t / C_(t-1) - 1` | 当日收盘收益更强 |
| `GAP` | `O_t / C_(t-1) - 1` | 隔夜高开更强 |
| `INTRADAY` | `C_t / O_t - 1` | 日内开盘到收盘更强 |
| `RANGE` | `(H_t - L_t) / C_(t-1)` | 当日振幅更大 |
| `CLV` | `(2*C_t - H_t - L_t) / (H_t - L_t)` | 收盘越靠近当日最高价 |

单窗口因子，窗口 `N in {5,10,20,40,60}`：

| 因子 | 定义 | 值越大表示 |
|---|---|---|
| `ROC(N)` | `C_t / C_(t-N) - 1` | N 日正向动量更强 |
| `PRICE_MA(N)` | `C_t / Mean(C,N) - 1` | 当前价格高于均线更多 |
| `VOL(N)` | `Std(DAYRET,N, ddof=0)` | N 日收益波动更高 |
| `TS_RANK(N)` | 当前 `C_t` 在最近 N 个收盘中的平均百分位秩，映射到 `[0,1]` | 当前价格在窗口内位置更高 |
| `RSV(N)` | `(C_t-Min(L,N))/(Max(H,N)-Min(L,N))` | 收盘更靠近 N 日最高区间 |

`TS_RANK` 使用平均秩处理并列值；映射采用 `(average_rank-1)/(N-1)`，全相等时取 `0.5`。

双窗口因子：

```text
MA_RATIO(short, long) = Mean(C,short) / Mean(C,long) - 1
short,long in {5,10,20,40,60}, short < long
```

共有 `5 + 5*5 + C(5,2) = 40` 个基础因子实例。上述方向采用直观的正向动量定义；
Qlib Alpha158 的 `ROC=Ref(C,N)/C` 和 `MA=Mean(C,N)/C` 是反向比值，本项目不照搬其
方向，也不把本实现标注为 Alpha158 原样复刻。

### 2.3 窗口、缺失与停牌

- 所有 `REF` 和滚动窗口按全市场统一交易日历位移，不按“该 ETF 最近 N 个有成交日”位移。
- 停牌、零成交、缺行和上市前输入均视为 `NaN`，不前值填充，也不跳过后拼成满窗口。
- `REF(x,N)` 要求 `x_(t-N)` 有效。
- `MEAN(x,N)`、`VOL`、`TS_RANK`、`RSV` 和均线类因子要求连续 N 个交易日输入全部有效。
- 这比 Qlib 的 `rolling(..., min_periods=1)` 更严格，目的是避免停牌后用少量残余观测伪装完整窗口。
- 因子可使用研究期开始前的历史做 warm-up，但不得使用 `t` 之后数据。

### 2.4 CPU/GPU 容差

- 基础因子和固定公式：有限位置、`NaN` 位置必须一致；有限值 `rtol=2e-5, atol=2e-6`。
- scorer 每日选中符号必须一致；非近似并列信号的排名必须一致。
- 每日超额收益和总 reward 的 CPU/GPU 绝对差不超过 `1e-6`。
- 信号差小于上述容差导致的并列，统一按 universe 配置中的 symbol 顺序稳定破同分。
- 若真实 GPU smoke 证明某条容差不可达，只能在查看验证期和样本外前，以独立规格修订记录调整。

## 3. V3A 数据与身份契约

### 3.1 新 dataset

保留现有 `data/processed/v3/dataset/` 不变；新增：

```text
data/processed/v3a/dataset/panel_v3a.npz
data/processed/v3a/dataset/dataset_manifest.json
```

`panel_v3a.npz` 至少包含：

```text
absolute_ohlc   [35,4,T]  # event_qfq open/high/low/close，仅内部因子与成交使用
relative_ohlc   [35,4,T]  # open_rel/high_rel/low_rel/close_rel，仅治理和交叉核验
tradable_mask   [35,T]    # t 日当时可知的信号可选与成交状态
symbols         [35]
dates           [T]
absolute_features = [open,high,low,close]
relative_features = [open_rel,high_rel,low_rel,close_rel]
```

上市前、缺行、零成交和停牌位置的研究输入统一置 `NaN` 且 `tradable_mask=False`。本地治理
parquet 仍保留原始行供审计，但不成为训练运行时依赖。

构建脚本为 `scripts/v3a/build_dataset.py`，输入：

- `data/processed/v3/governance/etf_daily_event_adjusted.parquet`；
- `data/processed/v3/dataset/panel_relative_price_v3.npz`；
- `data/processed/v3/dataset/dataset_manifest.json`；
- `configs/research_v3_universe.json`。

相对 OHLC 的复核必须发生在治理长表应用研究 mask **之前**：严格复用
`add_relative_ohlc` 的“每只 ETF 上一条源数据行 close”语义，再按当前行 tradable 状态写入
panel，并与上游 V3 panel 比较。禁止从已将停牌/缺行位置置为 `NaN` 的 V3A absolute array
反推上游 relative，因为零成交后的恢复日和跨缺行恢复日会改变分母。保存后的 masked absolute
array 只用于验证统一交易日历上的因子缺失语义。

### 3.2 manifest

manifest schema 固定为 `etf-v3a-dataset-v1`，身份必须覆盖：

- panel 文件名和 SHA-256；
- 上游 V3 `dataset_id=etf-relative-price-v3-989c5d80a4e0` 与 panel SHA；
- 治理 parquet SHA-256、universe JSON SHA-256；
- symbols、日期范围、shape、tradable 数量和特征名；
- 事件复权、相对价格、mask 的文字语义和版本；
- `available_count_min=10` 与有效起点 `2016-08-09`；
- `flow_features_exposed=false`。

除 `dataset_id` 和 `dataset_fingerprint` 外的规范 JSON 计算 fingerprint，ID 格式为：

```text
etf-v3a-<fingerprint前12位>
```

loader 每次运行都复算 panel SHA 和 fingerprint，不接受只看文件名的弱校验。

### 3.3 V3APanel 与因子缓存

新增专用 `V3APanel`，不修改共享 `MarketPanel` 的旧语义。它明确区分：

- 内部绝对 OHLC；
- 治理相对 OHLC；
- t 日 tradable mask；
- 由 factor spec 预计算的 40 个无尺度因子缓存。

VM 的公开执行接口只接收因子缓存和 mask；scorer 单独接收绝对 open 与 mask。这样即使词表
实现错误，也没有裸价格 terminal 可以压入公式栈。

### 3.4 ResearchSpec

`ResearchSpec` schema 固定为 `etf-v3a-research-spec-v1`，规范 JSON 生成 `research_spec_id`，
强绑定：

- dataset ID、fingerprint、panel SHA 和上游 V3 身份；
- 训练/验证/最终样本外日期切分；
- factor spec 版本、40 个实例定义、窗口和缺失语义；
- vocab 版本、token ID/名称、grammar 版本、最大长度；
- scorer 版本、完整参数和成交语义；
- canonicalizer、相似度和候选漏斗版本；
- Git commit 与 V3A 相关源码内容 fingerprint。

artifact 和 checkpoint 同时保存完整 spec 和 `research_spec_id`。任一字段不一致均硬拒绝；
V1/V2 schema、vocab、scorer 和 checkpoint 必须明确报错，不做兼容降级。

## 4. 参数化公式语言

### 4.1 固定 token ID

公式词表版本：`etf-v3a-formula-v1`。

```text
 0 DAYRET       1 GAP          2 INTRADAY    3 RANGE       4 CLV
 5 ROC          6 PRICE_MA     7 VOL         8 TS_RANK     9 RSV
10 MA_RATIO
11 WIN_1       12 WIN_5       13 WIN_10     14 WIN_20     15 WIN_40     16 WIN_60
17 ADD         18 SUB         19 MUL        20 NEG        21 ABS        22 SIGN
23 REF         24 MEAN
25 CONST_0     26 CONST_1
```

policy token：`PAD=0, BOS=1, EOS=2`，公式 token 从 offset 3 开始，总词表 30。

### 4.2 语法

组合表达式沿用后缀 RPN；参数化基础因子采用“因子族后紧跟参数”的原子语法：

```text
DAYRET                              -> DAYRET
ROC(20)                             -> ROC WIN_20
MA_RATIO(5,20)                      -> MA_RATIO WIN_5 WIN_20
ADD(DAYRET, ROC(20))                -> DAYRET ROC WIN_20 ADD
REF(PRICE_MA(20),5)                 -> PRICE_MA WIN_20 WIN_5 REF
MEAN(DAYRET,10)                     -> DAYRET WIN_10 MEAN
```

约束：

- `ROC/PRICE_MA/VOL/TS_RANK/RSV` 后只允许 `WIN_5..WIN_60`；
- `MA_RATIO` 后依次生成 short、long，第二个窗口必须大于第一个；
- `REF` 允许 1/5/10/20/40/60；`MEAN` 只允许 5/10/20/40/60，去掉恒等的 `MEAN(x,1)`；
- `ADD/SUB/MUL` 消耗两个表达式；`NEG/ABS/SIGN` 消耗一个表达式；
- `EOS` 只在“无待填参数且表达式栈恰为一个值”时开放；
- 最大 15 个公式 token，不含 BOS/EOS/PAD；合法单 token 公式可以立即 EOS；
- action mask 同时追踪类型栈、待填参数、剩余 token 是否足够闭合，非法序列不得采样。

builder 输出 AST、规范公式文本和编译后的 VM 指令。CPU/GPU VM 不重复解释半合法 token 流。

## 5. Scorer 因果真值

### 5.1 每日选择与收益

对每个信号日 `t`：

1. 先按第 5.2 节只用数据/mask 和完整标签条件，为每个分段预计算所有公式共用的信号日集合
   `D_split`；公式不得改变 reward 的日期分母。
2. 对 `t in D_split`，`A_t = tradable_mask[:,t]`，要求 `|A_t| >= 10`；排名不得查看未来 mask。
3. `k = clip(ceil(0.20 * |A_t|), 2, 4)`，与旧研究的仓位数量级保持一致。
4. CPU/GPU 排名统一使用 float32 signal，同值按 universe symbol 顺序稳定破同分。
5. 只在 `A_t` 内按有限 signal 降序稳定排名；任一 `t in D_split` 的有限 signal 少于 k，
   整条公式标为 `insufficient_daily_signal`，不能删除该日或缩小 k。
6. 选中 top-k 后才检查 `t+1`：不能以有限正 open 成交的槽位收益记 0，不补买下一名。
7. 可买槽位计划在 `t+1+10` 的开盘卖出；若当天不能成交，顺延到第一个可交易且 open 有限为正的日期。
8. 对 `A_t` 的每只 ETF 用同样规则生成池基准收益：次日不能买记 0，已买后卖出顺延。
9. 当日主分数为 `mean(top-k槽位收益) - mean(A_t全部ETF收益)`。
10. 训练 reward 固定为 `D_train` 全部日期主分数的等权平均；不同公式的均值分母完全相同。

不能成交是收益语义，不是排名资格。CPU 与 GPU scorer 共享预计算的 buy index、planned sell
index、actual sell index 和 forward-return/cash 矩阵，避免两份成交逻辑漂移。

### 5.2 分段边界

- train：信号日 `2016-08-09..2021-12-31`；
- validation：信号日 `2022-01-01..2022-12-31`；
- final OOS：信号日 `2023-01-01..数据末日`。

因子 warm-up 可以读取分段开始前数据。每个 `D_split` 仅由以下条件预先生成：

- `|A_t| >= 10`；
- `t+1` 位于同一分段；
- 对 `A_t` 中每只 ETF，次日不可买可确定为现金 0；若次日可买，则实际顺延卖出日在同一分段。

若任何已买 ETF 在分段结束前没有可用卖价，则该日期不进入所有公式共用的 `D_split`，不能从
基准池中单独删除该 ETF。标签完整性可以使用未来数据确定“是否存在标签”，但不得改变 `A_t`、
top-k 排名或某一公式单独的日期集合。这样只损失统一的边界日，不产生公式特定的隐含择时。

### 5.3 审计指标

以下不进入 reward：

- 选中槽位的 10 日平均绝对收益、中位数、正收益比例；
- 每日横截面 Spearman Rank IC，至少 10 个有效 ETF，报告均值、标准差、ICIR 和正 IC 比例；
- 10 个起始 offset 的非重叠 top-k 执行账本：只做固定 10 日持有、无法买入留现金、卖出顺延，
  报告总收益和最大回撤的中位数/最差值；不加入止损、rank exit 或市场空仓；
- 港股 ETF、ETF 类别和单 ETF 的收益贡献拆解；
- 旧“未来 mask 预筛” scorer 与修正 scorer 的差异，仅作偏差审计。

## 6. 公式质量、去重与候选漏斗

### 6.1 质量门禁

- 训练有效区间去掉最长 60 日 warm-up 后，公式有限值覆盖率至少 95%；
- 信号全局标准差必须大于 `1e-12`；
- 至少有 252 个可计分日；
- 非有限、常数、低覆盖和无 scorer 日分别记录原因；所有尝试仍计入预算。

### 6.2 规范化

只做可证明的 AST 规则，不依赖浮点结合律：

- `ADD/MUL` 的两个直接子节点按 canonical hash 排序，但不跨层 flatten；
- 常数子树折叠；`x+0=x`、`x-0=x`、`x*1=x`；不做 `x*0=0`，因为它会吞掉原式的 `NaN`；
- `NEG(NEG(x))=x`、`ABS(ABS(x))=ABS(x)`、`SIGN(SIGN(x))=SIGN(x)`；
- `REF(x,0)` 不存在；`MEAN(x,1)` 在 grammar 层禁止；
- 参数化因子展开为唯一 AST 节点，`MA_RATIO` 参数顺序固定。

canonical AST JSON 计算 `formula_hash`。结构 hash 相同只保留首次尝试计数和最高训练 reward 记录。

### 6.3 信号相似度

只用训练期信号计算公式两两相似度：逐日对重叠且至少 10 只 ETF 的信号算 Spearman，
将 `rho` 截断到 `[-1+1e-7, 1-1e-7]` 后按 `n-3` 对 Fisher-z 加权平均；至少 252 个重叠日。
不足 252 个重叠日的公式不得进入候选漏斗，记为 `insufficient_similarity_overlap`。

- `rho >= 0.995`：视为信号重复，只保留训练 reward 更高者；
- `rho >= 0.90`：视为同一多样性簇，但不等同于重复；
- 负相关不取绝对值，因为反向排序代表不同的 ETF 选择。

多样性簇在读取任何 2022 指标前确定并落盘：候选按“训练 reward 降序、token 更短、canonical
hash 更小”排序；依次与各簇固定代表比较，分配给第一个 `rho>=0.90` 的代表，否则新建簇；
簇代表始终是该簇首条公式，不随后续成员变化。`cluster_id`、代表 hash 和成员表写入训练期
artifact，2022 选择器只能读取该结果，不得重新聚类。

### 6.4 训练期 50 条候选

按 token 长度建三个流式 heap，每桶先保留训练 reward 最高的 500 个 canonical unique 公式：

```text
短：1..5 token
中：6..10 token
长：11..15 token
```

最终选择：

1. 第一轮按 reward 降序，每个预先固化的多样性簇最多一条，配额短/中/长为 `10/10/5`；
2. 第二轮继续按 reward 降序，要求 `rho < 0.995`，补到总配额 `20/20/10`；
3. 某桶不足时按 reward 向其他桶转移空缺，但仍执行 `rho < 0.995`；
4. 排序同分依次用更短 token、较小 canonical hash 破同分。

Transformer 和随机 baseline 使用完全相同的漏斗。非法、语义无效、结构重复和信号重复均在
尝试计数器递增后处理。

### 6.5 2022 筛选与最终冻结

- 50 条候选全部进入 2022，一次性计算 validation 指标；
- 先按 validation 主 reward 降序，每个已落盘的训练期 `cluster_id` 最多一条，选最多 5 条；
- 若不足 5 条，再允许同簇但仍禁止 `rho>=0.995` 重复；
- 同分依次看训练 reward、更短 token、canonical hash；
- 5 条公式、ResearchSpec、代码 commit 和审计配置写入只读 freeze manifest；
- 冻结后才允许运行 2023+ 审计，结果只报告，不据此换公式或改阈值。

### A3：实现语言、builder、action mask 和 VM

  action 上均匀抽样，不另设隐式停止概率。

**验收**：枚举短序列验证合法/非法边界；采样 10,000 条语法非法率必须为 0；

- 实现主超额 reward、绝对收益、Rank IC 和非重叠 offset 回撤审计；
- 保留旧 scorer 仅用于修正前后差异报告。

**验收**：测试直接断言选中 symbol、buy/sell date、现金槽位和每日超额收益，不只断言汇总数。

### A5：实现 torch scorer 与 CPU 对照

- CPU 先预计算因果 target/index 张量；
- torch scorer 只做批量排名和聚合，不复制卖出顺延规则；
- 在 CPU device 上先完成 torch/NumPy golden test。

**验收**：合成 panel 上选择结果完全一致，收益达到第 2.4 节容差。

### A6：实现候选漏斗、artifact 和 checkpoint

- artifact 保存原 token、AST、hash、train 指标、ResearchSpec；
- checkpoint 保存 model/optimizer/RNG、attempt 计数、候选 heap、完整研究身份和训练配置；
- checkpoint 同时保存独立随机生成器状态和版本化 candidate state；训练漏斗 artifact 保存每个
  cluster 的代表、完整成员、最终 50 条及排序规则；
- resume 先验身份再加载权重；V1/V2 产物必须硬拒绝。

**验收**：同 run 中断恢复后的下一批采样、attempt 计数和候选结果与不中断运行一致。

Torch VM 必须按最大实际栈深和显存预算自动切 formula chunk；不得为完整 batch 分配
