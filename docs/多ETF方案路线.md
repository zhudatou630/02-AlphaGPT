# 多 ETF AlphaGPT 迁移方案路线

> 本文档讲**逻辑与思路**，不讲实现细节。
> 目标：以 AlphaGPT 的思想为骨架，搭一套属于我们自己的「多 ETF 横截面因子挖掘 + 验证 + 执行」系统。
> 起步标的：~15-20 只 A 股宽基 ETF，日频，akshare 免 token。

---

## 0. 定位：继承什么、改什么

### 继承 AlphaGPT 的思想骨架
- **三件套**：Transformer 生成公式 token → StackVM 执行成因子值 → REINFORCE 用打分器分数训练生成器
- **公式即 artifact**：训练产出可读公式（序列化文件），下游只消费它，运行时零耦合
- **信号/风控/执行三层分离** + **多重退出防线**
- **解耦原则**：基础模块保持单一职责（挖信号），复杂度往上叠，不焊进基础模块

### 改掉 AlphaGPT 的具体实现（它是 Meme 币量身做的）
- 数据接口：Birdeye/PostgreSQL → akshare
- 执行接口：Solana 链上 → A 股券商（受 T+1 约束）
- 打分器：从"全买中位数"（有甲/乙错配缺陷）→ **top 分位 × 视界N**（纯信号质量，策略对齐、摩擦下沉验证层）
- 验证层：补 AlphaGPT 缺的 **OOS 回测 + 纸面交易**
- 训练稳定性：接上 critic 降方差、多 seed 看稳健

### A 股关键约束（与 Meme 根本不同）
| | AlphaGPT（Meme） | 我们（A 股 ETF） |
|---|---|---|
| 频率 | 1 分钟 | 日频 |
| 成本 | 0.6% 单边（滑点极高） | 万几手续费，滑点极低 |
| 交易制度 | 随时买卖 | **T+1**（当天买次日才能卖） |
| 风控重点 | 流动性枯竭、蜜罐 | 涨跌停、停牌 |
| 品种池 | 300-500 币，成员流动 | ~20 只宽基 ETF，相对稳定 |
| 执行 | 链上即时 | 券商接口，有延迟 |

> ⚠️ **T+1 最该提前意识**：退出信号当天产生、**次日开盘才能执行**，不能日内止损。这直接改变验证层和执行层的设计。

### AlphaGPT 是可组合的信号发现原语（本路线选其中一种用法）
AlphaGPT 对"universe/features/scorer 怎么来"不关心，只负责"给定这三者找最优信号"。所以它能插进不同流水线，**多 ETF 轮动只是其中一种用法**：

| 模式 | 怎么用 | 语境由谁定 |
|---|---|---|
| **整universe轮动**（本路线） | AlphaGPT 既定池子又找信号 | AlphaGPT 自己 |
| 预筛+发现 | 人按技术形态筛池子，AlphaGPT 找筛后池内细分信号 | 人的形态规则 |
| 分regime分别训 | 不同市场状态各训一公式，按状态切换 | 人的状态划分 |
| 纯研究工具 | 不上实盘，只发现候选因子给传统模型用 | —— |

**关键认知**：思维操作化**分布在整条流水线**，不只发生在 AlphaGPT 内部。预筛模式里，"形态筛"编码一处信念（外部），"AlphaGPT 信号"编码另一处（内部）。本路线选"整universe轮动"起步（最简单），但要知道换模式只是换"信念编码在哪一层"。

> 顺带：预筛模式里"每天按形态筛"本质就是**动态 universe**（成员天天变），机制和 universe mask 一样、要防前视。所以"动态池"不是要不要的问题，是"按什么规则动"的问题。

## 1. 总体思路：一根主线 + 两根柱子

### 一根主线：真实度逐层递增
整套系统从训练到实盘，**每层加一层真实度**，训练层不需要跟实盘一样真实——中间层就是干这个的：

```
打分器(top分位×视界N, 纯信号质量无摩擦)
   ↓ 加摩擦(成本/退出规则/T+1)
验证层 OOS(净收益, 含波段退出模拟)
   ↓ 加实时+真实延迟
纸面交易(实时数据模拟)
   ↓ 加真钱
实盘
```

**核心区分：策略 vs 摩擦**
- **策略（选股规则 top分位 + 持有视界 N）**：打分器和实盘**共享**——这是"我们在挖什么策略"，不是执行复杂度。波段性靠"视界N"吸收，不靠退出规则
- **摩擦（成本/滑点/退出规则/T+1）**：只在验证层及以后，**不进打分器**——这是执行真实度

这样打分器既简单（无摩擦、纯信号质量）又在策略层与实盘对齐（共享选股+视界），避免 AlphaGPT 的甲/乙错配（训练挑中甲实战平庸、淘汰乙实战爆赚），又不过度耦合。

### 两根柱子：动代码前先纸上定
| 柱子 | 决定什么 | 我们的定法 |
|---|---|---|
| **词表** | 能表达什么（搜索空间天花板） | 固定 ETF 池用**时序 token** 起步；横截面 token **可选**（详见 §3.①） |
| **打分器** | 优化什么（训练指南针） | **top 分位 × 视界N**（纯信号质量，无摩擦，详见 §3.②） |

### 安全网：验证层兜底（结构上必需，不是可选）
柱子都可能有偏差，验证层（OOS+纸面）负责把偏差在真钱前暴露。**代理松不可怕，没兜底才可怕。**

更深一层：验证层是**结构上必需**，不是"加了更好"。因为打分器是个优化器，**优化器按构造不能修改自己的目标**——目标是它的输入，它只能优化不能反思。所以"结果反推训练"必须有框架之外的元层来做，AlphaGPT 不提供，我们必须建。验证层就是这个元层的第一环：它发现"理念→打分器"的编码错误，触发回去修柱子再训。

### 盖房原则：渐进式
先用**手写固定公式**跑通"数据→打分器→验证"，确认懂全流程；再开 Transformer 训练。两件新事（多品种数据结构、RL 训练）不同时压上来。

## 2. 架构分层（地基 → 上层）

```
┌──────────────────────────────────────────────────────────┐
│ ⑥ 监控层    持仓/净值/日志/一键止损看板                      │
├──────────────────────────────────────────────────────────┤
│ ⑤ 执行层    风控+仓位+退出规则+券商下单（T+1，真钱）          │
├──────────────────────────────────────────────────────────┤
│ ④ 验证层    OOS(净收益+波段退出+T+1) → 纸面交易（摩擦在这） │  ★安全网(结构必需)
├──────────────────────────────────────────────────────────┤
│ ③ 信号发现核心  Transformer + VM + REINFORCE（三件套）      │
├──────────────────────────────────────────────────────────┤
│ ② 打分器层   top分位×视界N（纯信号·不焊摩擦）               │  ★柱子二
├──────────────────────────────────────────────────────────┤
│ ① 词表层     时序token起步（固定池）；横截面token可选         │  ★柱子一
├──────────────────────────────────────────────────────────┤
│ ⓪ 数据层     akshare 拉多ETF日线 → [N,F,T] 张量 + universe口│
└──────────────────────────────────────────────────────────┘
```

**依赖方向**：从下往上搭。①词表和②打分器是"先想清楚"的决策点，动手前定，不是边写边调。**摩擦只从④验证层开始出现，①②③都不含摩擦。**

## 3. 逐层讲我们的逻辑与思路

### ⓪ 数据层 —— 地基
**职责**：把多只 ETF 日频行情组织成规整 `[N品种, F特征, T时间]` 张量。

**思路**：
- akshare 免 token 拉 ~20 只宽基 ETF 日线（510300/510500/159915/588000/510050/512760/512660/512800…）
- **选 ETF 不选个股**：ETF 历史干净、不退市、上市早、数据好对齐；个股停牌/退市/历史不一，脏数据会淹没方法学习
- 数据是**全池规整矩阵**（每只 ETF 完整历史），动态池的"成员变化"将来交给 universe mask，不在数据层搞锯齿
- 这层只存原始 OHLCV，**不算特征**（算特征是词表层的事）

**与 AlphaGPT 差异**：它 Birdeye+PostgreSQL+TimescaleDB 重栈；我们 akshare 轻量起步，20只×10年日线≈5万行，pandas/parquet 足够，不需要数据库。

**注意点**：
- 用前复权(qfq)保证价格连续
- 留 universe mask 口子（初期全 True），为将来动态池铺路
- ⚠️ **"固定池"历史上并不固定**：20 只 ETF 上市日期不同，早期数据缺失。不能 ffill 没上市的，要么回测起点选在"都已上市"之后，要么用 available-universe（每天只用当时已上市的）
- ⚠️ **宽基 ETF 分化小是最大可行性风险**：宽基相关性高、池小，top 分位可能和随便选差不多、没 alpha。这是"池子配不配 top 选股"的问题，不是打分器问题——验证层会直接揭示（夏普低）。届时换更分化的池子（行业 ETF/个股），不是改打分器

### ① 词表层 —— 柱子一
**职责**：定义"特征 token + 算子 token"，圈定公式搜索空间。

**思路**：
- **固定 ETF 池起步：用纯时序 token 即可**——这是审计纠正的关键点
  - 池小（~20只）、ETF 相关性高、分化小，"相对强度"信号噪声大
  - "买 top-K"的执行层**已经做了横截面选择**：哪怕信号是纯时序的，最后买"时序信号最强的前K只"本身就是横截面选股
  - 所以公式不一定非得用横截面 token
- **横截面 token（CS_RANK/CS_ZSCORE 等）是可选**，不是地基必需：
  - 留到将来**池子变大变多样**（行业 ETF/个股）或**池子变动态**（成员天天变）时才升级为必需
  - 起步不强加，避免给小固定池塞用不上的 token 稀释搜索
- 算子覆盖：算术/条件(GATE)/时序(DELAY/DECAY/MA)/非线性(ABS/SIGN)
- 词表"精而覆盖全"，不是"多"——加无用 token 只稀释搜索、不抬天花板

**为什么是柱子**：词表外的信号永远搜不到。但"补什么"要匹配当前池子性质——固定小池不必上横截面，别提前过度设计。

**与 AlphaGPT 差异**：它只有时序 token；我们起步也是时序 token（看似一样），但**预留了横截面 token 的扩展位**，等池子升级时再补——区别在"有意识地推迟"，不是"没想到"。

### ② 打分器层 —— 柱子二
**职责**：给定公式+数据，输出一个分数（Transformer 进化的目标）。

**思路（第一性定稿）**：
- **打分器 = top 分位 × 视界 N 的收益**：t 时刻按信号排序取 top 分位，算它们未来 N 天的平均收益，对时间求平均
- **这是纯信号质量度量**，不是实战模拟：
  - 幅度敏感 → 解决甲/乙（甲 top 收益+2%、乙 top 收益+45%，分得出）
  - 时段匹配 → N=波段天数（如 5-10 天），在对的视界上评估预测力
  - 无摩擦 → 不含成本/退出规则/T+1
- **波段性靠"视界N"吸收，不靠"退出规则"**：之前一度想把波段退出规则塞进打分器，第一性审视后发现那是执行渗漏——"打算持有多久"是预测视界参数（属信号性质），"止损/止盈/移动止盈"是执行机制（属摩擦）。前者进打分器，后者进验证层
- **为什么不用 rank IC**：rank IC 只看排名不看幅度，甲（8个都+2%）和乙（2个+50%）rank IC 都高，分不出
- **为什么不用全实盘模拟**：把摩擦焊进基础模块，违反"保持简单"
- **去掉 AlphaGPT 的 activity<5→−10 惩罚**：误杀精选型公式，是甲/乙翻车元凶之一

**为什么是柱子**：打分器是训练指南针，指错方向 Transformer 越训越偏。它必须是"纯信号质量"——只问"信号顶部在目标视界有没有预测力"，不掺执行。

**与 AlphaGPT 差异**：它"全买+中位数+activity惩罚+退出焊在里面"（多重错配）；我们"top分位×视界N"（纯信号质量，摩擦全下沉验证层）。

**注意点**：⚠️ **T+1 改变收益对齐**。T+1 下最早"t收盘算信号→t+1开盘买→t+2开盘才能卖"，所以视界N的收益必须从 t+1 开盘起算（如 open[t+1]→open[t+1+N]），不能用同日收益（否则前视偏差）。N 天持有期天然 T+1 兼容（持仓≥1天）。

### ③ 信号发现核心 —— 三件套
**职责**：Transformer 生成公式 token，VM 执行成因子值，REINFORCE 用打分器分数训练生成器。

**思路**：
- **三件套逻辑原样继承**（已验证思想）
- **接上 critic**：AlphaGPT 定义了 critic 却没用，我们接进 advantage（`reward - critic_pred`）降方差
- **多 seed 训练**：5-10 个 seed 看最终分数分布，只信跨 seed 稳健的结果；单 seed 暴利不可信
- **公式即 artifact**：训练产出序列化公式，下游零耦合
- 训练循环本身和单品种几乎一样（外层遍历公式 batch），多品种只是 VM 输出多一维、打分器多一步 top分位聚合

**与 AlphaGPT 差异**：critic 真用上、多 seed、数据 `[N,F,T]`。

### ④ 验证层 —— 安全网（AlphaGPT 缺，我们补）
**职责**：在真钱前，把"打分器/词表/模型"的偏差暴露。**所有摩擦在这一层登场。**

**思路**：
- **第一道闸：OOS 样本外回测**
  - 训练用前段历史（如 2015-2022），检验用后段（2023-2025）
  - 检验用**实战级模拟**：top-K 选股 + 退出规则 + T+1 + 成本/滑点
  - 输出年化/夏普/最大回撤/卡玛，画净值曲线 vs 基准
  - 回答："公式在没见过的历史上、含真实摩擦下，还行不行"
  - **这一步把打分器的"毛收益"翻译成"净收益"**——摩擦差距在这里显现
- **第二道闸：纸面交易**
  - 用**实时**数据（每天收盘后跑），按实战逻辑模拟下单，**不下真单**
  - 跑 1-3 个月，对比纸面 vs OOS 预期
  - 回答："实时数据+真实延迟下，还行不行"
- **两道闸的逻辑**：打分器是代理（毛收益，无摩擦），代理松不可怕，验证层兜底。摩擦差距、实时偏差都在这里抓

**迭代回路**：
- OOS 不过 → 回去调词表/打分器/超参 → 重训
- OOS 过但纸面不及预期 → 多半摩擦模型不准（滑点/延迟）→ 调执行参数

**与 AlphaGPT 差异**：它训练直跳实盘；我们中间插两道闸，且摩擦全部在这里登场。

**注意点**：换手成本在这层抓——打分器是纯信号质量（不建模交易），高换手公式可能毛信号好但扣成本就蔫。OOS 净收益会把这层揭出来;若频繁因换手翻车，再考虑给打分器加轻换手惩罚（借鉴 AlphaGPT 的成本感知），但起步不必。

### ⑤ 执行层 —— 真钱落地
**职责**：消费公式，实时打分，风控+仓位+退出+下单。

**思路**：
- **保留三层分离**：信号（公式算分）→ 风控（涨跌停/停牌/仓位）→ 执行（券商下单）
- **退出规则适配 T+1**：止损/止盈信号当天产生，**次日开盘执行**（不能日内卖）
- **持仓粘性 + 退出触发**：不轮动，只在退出规则触发时腾坑
- **小仓位起步**：极小资金验证执行链路和真实滑点
- **状态持久化 + 优雅停机 + 紧急止损**：照搬 AlphaGPT 好设计

**与 AlphaGPT 差异**：券商 vs 链上；T+1；涨跌停/停牌 vs 流动性/蜜罐；有延迟。

**注意点**：执行层最后才碰，验证层没过绝不碰真钱。

### ⑥ 监控层 —— 并行辅助
**思路**：轻量起步，重点是**一键止损**和**持仓可视化**。AlphaGPT 的 Streamlit 可参考不照搬。

## 4. 流程方向与依赖

### 依赖图
```
数据层 ──► 词表(特征从数据算) ──► 打分器(消费词表+数据, top分位×视界N)
                                       │
                                       ▼
                                 信号发现核心(用打分器当目标)
                                       │
                                       ▼
                                 验证层(加摩擦: OOS净收益+退出+T+1 → 纸面)
                                       │
                                       ▼
                                 执行层(真钱, T+1)
                                       │
                                       ▼
                                 监控层(并行)
```

### 建造顺序
1. **先想清楚**：词表 + 打分器（两根柱子，纸上定）
2. **数据层**：akshare 拉数据成 `[N,F,T]`
3. **词表落地**：时序 token（固定池）
4. **打分器+验证落地**：手写固定公式跑通 top分位×视界N(打分器) → 净收益+退出(验证)，确认懂全流程和摩擦差距
5. **信号发现核心**：接 Transformer+VM+REINFORCE，开训练
6. **OOS 验证**：训练→检验→不行回 1/3/4 调
7. **纸面交易**：OOS 过→实时模拟→不行调摩擦模型
8. **小仓位实盘**：纸面过→真钱小仓→逐步放量
9. **监控**：并行搭，越早越好

### 三个迭代回路
- **研究回路**：训练 ↔ OOS。OOS 不过→调词表/打分器/超参→重训。最频繁。
- **落地回路**：OOS ↔ 纸面。纸面不及预期→多半摩擦模型不准→调执行参数。
- **稳健回路**：多 seed ↔ 决策。只信跨 seed 稳健公式；单 seed 暴利不可信。

## 5. 关键决策点与权衡

| 决策点 | 选项 | 我们的倾向 | 权衡 |
|---|---|---|---|
| 标的池 | ETF池/个股池 | ETF起步 | ETF干净好学但横截面分化小；个股空间大但脏。先ETF学框架，后可换个股 |

## 6. 建造里程碑（地基 → 上层）

每阶段有"完成标准"，达标才进下一阶段。

### Phase 1：立地基（数据 + 词表）
- **做**：akshare 拉数据成 `[N,F,T]`；定时序 token
- **完成标准**：能打印每只 ETF 特征张量形状正确；词表清单定稿（纸上）
- **不碰**：模型、训练

### Phase 2：打分器 + 验证 + 固定公式跑通
- **做**：实现打分器(top分位×视界N) + 验证(净收益+退出+T+1)；手写2-3条固定公式跑全流程
- **完成标准**：看懂"公式→信号→top分位选股→视界N收益(打分器)→净收益(验证)"全流程；手动验证分数合理，理解纯信号/含摩擦的差距
- **不碰**：Transformer

### Phase 3：接 Transformer 训练
- **做**：三件套接上，REINFORCE 训练，接 critic，多 seed
- **完成标准**：训练收敛，best formula 可读，跨 seed 稳定
- **不碰**：OOS 严格检验（这阶段先看训练跑通）

### Phase 4：OOS 样本外回测
- **做**：训练/检验时段切分，OOS 检验（含摩擦），输出夏普/回撤/净值
- **完成标准**：OOS 夏普达标（如>1），跑赢基准；不达标回 Phase 1/2/3
- **不碰**：实时数据

### Phase 5：纸面交易
- **做**：每天收盘后实时数据模拟下单，跑1-3个月
- **完成标准**：纸面与 OOS 预期一致（偏差可解释）；不一致调摩擦模型
- **不碰**：真钱

### Phase 6：小仓位实盘
- **做**：极小资金接券商，真钱跑，对比实盘 vs 纸面
- **完成标准**：执行链路稳定，实盘与纸面偏差小，逐步放量
- **并行**：监控看板

## 8. 一句话方向总结

**以 AlphaGPT 三件套+解耦思想为骨架，从地基往上搭：词表（固定池用时序token，横截面留到大池）和打分器（top分位×视界N，纯信号质量、策略对齐不焊摩擦）两根柱子先纸上立;摩擦（成本/退出规则/T+1）全部下沉到验证层;真实度逐层递增（打分器纯信号→验证层净收益→纸面实时→实盘真钱），每层有完成标准，验证不过绝不往上走。**

核心心法五条：
1. **策略 vs 摩擦分离**：打分器和实盘共享"选股规则+持有视界N"，不共享摩擦——波段性靠视界N吸收，不靠退出规则焊进打分器
2. **真实度逐层递增**：训练层不必跟实盘一样真实，中间层负责加真实度
3. **词表是天花板，打分器是指南针**：两根柱子先想清楚，但补什么要匹配当前池子性质（固定池不必上横截面）
4. **验证层是结构必需的安全网**：优化器不能自改目标，验证元层必须外置；代理松不可怕，没兜底才可怕
5. **AlphaGPT 是可组合的信号发现原语**：思维操作化分布在整条流水线（筛子/词表/打分器各编码一处信念），多ETF轮动只是其中一种用法；可换预筛+发现等其它组合模式
